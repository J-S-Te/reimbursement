# 报销运行与恢复

本仓库业务API、worker、migrate和authz-catalog分别构建，统一前端位于frontend/src/modules/reimbursement。V1.0 Word为业务设计权威来源，旧V0.1不同处不采用。

通过平台subsystem-access preview/operations受控接入，先部署项目接收协议，再启动报销生产者。真实凭据、公司主体、财务范围、费用职级、审批人、费用标准和收款资料由授权管理员配置，不提供全权限初始业务数据。

运行配置参见deploy/reimbursement.env.example。时间戳存UTC，单号及业务日期按Asia/Shanghai。数据库独立schema，禁止跨库读写。不得启用许可兼容放行。API与worker使用各自SERVICE_ID和许可材料，迁移不是常驻运行组件。

迁移前完成独立备份、校验和与恢复方案；受控操作时设置REIMBURSEMENT_MIGRATION_BACKUP_VERIFIED=true运行reimbursement-migrate。启动只检查SQL摘要与待迁移状态，不自动改库。MySQL DDL可能部分提交，失败后先检查schema与记录，不能直接回滚删除财务表或盲目重跑ALTER。

授权目录发布不依赖API已就绪：reimbursement-authz-catalog publish。目录完成后再分配reimbursement_admin（超级管理员，保持原角色编码）及各业务角色。当前报销目录v4共9角色/32权限，超级管理员通过独立expense.scope.tenant_all能力获得本租户全量范围；普通财务、审计和档案人员必须发布明确组织列表或显式tenant_all范围，未配置不获得组织财务范围，平台APPLICATION/普通动作集合不推导全量。职责分离、任务受理和租户隔离仍校验。目录口径以`authz/permission-manifest.yaml`与`authz/manifest_test.go`断言为准，运维核对前先跑authz测试（`go test ./authz`）。

任务表exp_job、exp_outbox通过租约领取、版本和owner提交。失联租约可接管，通常最多12次指数退避后FAILED；解析失败事实与审计尚未可靠落库时保持PENDING及有界退避，需恢复审计存储后继续处理，不能因次数上限丢失失败审计；应按稳定业务错误处理，不能删除财务事实。重投项目完整快照不会登记第二次付款。排查时以request_id/claim_id/event_id关联，禁止打印凭据和票面明文。

归档默认封存不可变清单与文件引用，不生成超20MiB的ZIP。付款与项目同步/归档故障隔离；已付款后归档失败不改付款状态。修复缺文件后经有权入口重试档案任务。最新失败包的受控重试创建明确前序关联的新档案版本与新资料截止，旧包及其截止保持不变；旧待重投任务以版本CAS终结，已领取任务继续持有原租约。已封存最新包不重复建包。项目对账比较实际贡献及效果分摊，不只比较cursor hash；物化行损坏用项目受控rebuild并记录reason。

首发导出最多100张、结果1MiB；超过则明确拒绝，避免静默截断。生成与下载重新授权。CSV仅包含单号、标题、状态、整数分应付额及币种，不含银行卡号。完整账号不进入列表、日志和项目事件。

解析使用指定提交的OFD与PDF库，20MiB输入、100MiB展开、100页及2048 ZIP条目边界；首发结果均待复核，不声称签章或税务查验。扫描、损坏、合并边界不明及票面缺字段需人工处理。PDF锁定库无法还原中文CID/ToUnicode字体，或多数非空字形缺失宽度时，会以镜像内的poppler-utils（pdftotext bbox-layout）词框后备提取；后备仍受100页、8MiB输出与子进程超时边界约束，不启用图片OCR。实际授权票样及金标准是上线前必需证据，合成结构测试不能替代完整票种验收。

规则v4补齐分字表头、分列合计、独立“小写”标签与紧邻括号续行；开票人统一保存在候选`issuer`与字段来源中，PDF标签和OFD结构化/标引均可提供。项目名称、单位、数量、单价、金额、税率/征收率和税额按实际明细保留，不推算缺失金额。已有解析结果是历史运行事实，不随升级重写；需要通过正常解析入口创建新运行。前端以项目名称卡片及发票号、日期、类型、总计金额胶囊展示，展开核对销售方、开票人、汇总和明细，仍需人工复核。

发布前依次执行：隔离MySQL全部迁移与并发不变量；真实平台OIDC/单点退出/授权撤销；文件上传原件/凭证/下载；正常技术与销售路线；付款/冲正/重付；项目600/400分摊/重复倒序/对账；归档缺文件；导出后撤权；UPDATE/ADOPT/RETRY和密钥轮换；备份恢复。按最小业务场景逐项验收，不一次性批量跑完整业务环境。

本轮岗位更正以用户2026-11-10最新要求为准：费用负责人直接取项目经理（服务项project_manager_id；项目级manager_identity_id），技术负责人为项目technical_director，销售负责人为项目sales_director。技术正常经理→会计，异常增加技术总监；销售正常销售总监→会计，异常增加财务负责人。初始业务岗位不使用报销本地同名人员映射；本地映射仅保留业务受控替代及财务首次/替代。

上线前须先同步项目目录v11（含最小sales_director）与报销目录v4，并给相关人员明确岗位及报销访问/审批授权。技术总监按项目组织、销售总监按已发布员工费用档案销售组织；后者仍须是申请人当前有效任职组织。不按姓名匹配或把项目技术组织当销售组织。经理和总监目录来源当前有效性在新业务任务办理前再验证，失效不静默改派，使用受控转交或新轮次救济。

新生成档案的history.approval_action_details保存各类动作的资格及转交证明，实际类型由父approval_actions.action区分；旧已封存包的approval_transfers原文及摘要不改写，不把普通通过/退回证明伪称为转交。


## 一期增量操作边界（2026-11-11）

- 解析锁定现有`zc310/ofd`与`ledongthuc/pdf`版本：OFD使用invoice.Extract优先结构化附件/标引；PDF优先按页文字坐标、标签与明细映射，锁定库只返回CID原始字形码或大多数字形无宽度时使用镜像内`pdftotext -bbox-layout`词框后备。无可靠文字、结构缺失或冲突进入解析异常/人工复核，不自动确认，不代表签章或税务验真。规则版本expense-invoice-v4；单次结果信封4MiB。冗余全文超预算时显式保留字段/明细证据和页锚点，标记EVIDENCE_COMPACTED_REFER_TO_ORIGINAL；不可约结果超限仍失败。
- 原件解析待处理池只显示当前租户本人最新FAILED/NEEDS_REVIEW/PARTIAL且尚无业务发票/实际来源的原件；不可变parse_run_id与任务parse_job_id不同，任务查询使用后者。
- 标准及审批预览只用于已保存本人草稿，绑定claim_id/expected_version；不保存、占票、排任务或写审计，正式提交重新核验。首次启用后编辑合并为自动更新，旧结果立即失效。
- 预付expense_nature=PREPAYMENT需匹配标准allow_prepayment=true、用途说明和独立claim.evidence证明；仍走原财务审批，审批快照显示重点复核及证明。历史空性质按原实际费用处理。不新增借款/核销账本。
- 票种deduction_priority=PRIORITY_REVIEW仅提示优先财务人工复核；NORMAL/空值按常规处理，不自动计算可抵扣税额或改变应付、核验状态。
- 项目统一档案采用目录整合：合同引用、任务/原始记录入口、报告版本、审核/回执/异常记录及报销档案聚合。原件与下载权限保留在来源系统；报销目录会话与响应viewer须匹配项目当前主体/租户，不合并实体ZIP、不继承项目权限。
- 列表批量导出只处理显式勾选的当前可见单据（最多100），后台生成及下载仍逐次复核当前权限。任务超期显示采用当前PENDING最近激活/变更满48小时，不是新增授权或SLA承诺。

本轮开发与验证证据在工作区`.ai/qa/reimbursement-phase1-fixes-20261111/`；本地单测、合成接口浏览器与隔离MySQL不能替代真实OIDC、文件网关、平台送达、授权真实票样及完整业务验收。没有部署测试服务器。

## 内容归类、会计复检与退回率（2026-11-11）

- 发票规则的 `content_mappings` 配置税码前缀或明细字面关键词；人工核对原件后保存 `content.lines`。内容命中优先，未命中回退票种默认；同级冲突、混合类别、部分未匹配进入人工归类，页面不自动建单。草稿保存按真实用票及发布版本重建只读依据，保留人工选值，不信任客户端结论。占用/消费票据内容走正式独立更正，不回写旧审批快照。
- 会计点击通过时执行冻结标准与当前票据合规复检。确定不合规真实退回，保存原因及案件证据、取消本轮待办、释放本单预留并可靠通知申请人；相同原通过命令重放实际退回结果。依赖故障、撤权、陈旧版本或账本损坏保持错误，不伪装业务退回；新标准不追溯旧单。
- 看板分母为当前创建日窗口内有真实提交快照的去重单据，分子为其中存在当前可见真实RETURN动作的单据；同单多轮只计一次，撤回、作废与差旅异常不算退回。零分母明确不计算，局部权限不披露隐藏项目的退回动作。

GitHub Actions在main非PR执行后端检查、不可变镜像构建和test环境受控部署；使用仓库ACR变量/密钥及test环境SSH配置。部署目录由DEPLOY_PATH指定，远端仅调用平台现有bin/deploy-service.sh，不独立docker启动或绕过许可/备份。首次上线须先发布支持报销的平台/文件网关、生产资产和项目接收能力，完成真实平台接入与API/Worker许可；仅配置GitHub部署密钥不代表这些条件已完成。缺运行材料必须真实失败，不把镜像暂存视为部署成功。
